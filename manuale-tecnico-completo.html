1. Scopo e metodo della documentazione

Questo documento è concepito come manuale di consegna: descrive il sistema per area funzionale e, nelle sezioni centrali, associa le funzioni JavaScript ai rispettivi compiti.

Regola di lettura: una funzione viene considerata “attiva” solo quando il suo utilizzo è compatibile con i riferimenti correnti delle pagine/moduli. I file in backup/, bck/ e pagine di prova non vengono trattati come runtime principale.
FonteUso
Repository GitHubFonte primaria del codice corrente.
HTMLMenu, pulsanti, struttura e script caricati.
JavaScriptLogica applicativa e comportamento runtime.
SupabasePersistenza, autenticazione e dati applicativi.
Documentazione tecnica esistenteContesto storico e vincoli di manutenzione.

2. Architettura generale

VISITATORE→visitatore.html→moduli pubblici→Supabase
ADMIN→admin.html→gestione tornei / contenuti→Supabase
ADMIN→tabellone.html→motore torneo→salvataggio
ADMIN→King→coppie variabili / classifica individuale

Il progetto usa HTML5, CSS3, JavaScript browser/ES6+, Supabase JS v2, Supabase Auth, PostgreSQL/Supabase, GitHub Pages e componenti PWA/service worker. Bove utilizza inoltre SheetJS/XLSX.

Flusso amministrativo

Nuovo torneo → dati torneo → numero squadre → giocatori calcolati → scelta formula → configurazione formula → creazione.

Flusso Bove

Apertura → identificazione torneo → caricamento stato → regole → formato/gironi → squadre → partite/campi/orari → risultati → classifiche → qualificate → KO → campione → salvataggio/reload.

Regole funzionali

  • Classifica individuale.
  • Vittoria 3 punti, pareggio 1, sconfitta 0.
  • PF, PS e differenza individuale.
  • Modifica manuale sempre disponibile.
  • Generazione automatica delle coppie.
  • Slot previsti: 6, 8, 10, 12 o manuale.
  • Giorni e orari dinamici.
Il test storico del King ha documentato 8 giocatori, 12 giornate, 4 coppie/giornata, 6 partite/giornata e 72 risultati; questi valori sono dati di test e non costituiscono da soli una certificazione del codice dopo modifiche successive.

15. Iscrizioni e partecipanti

Iscrizione

Il visitatore può essere indirizzato a iscrizione.html?torneo=ID. L'admin gestisce caricamento, approvazione, rifiuto e stato.

Partecipante

L'approvazione alimenta il contesto partecipanti del torneo.

Coppia

Le funzioni di costruzione coppie generano o organizzano le coppie in base alla formula.

Bove

Il torneo selezionato viene passato al motore Bove tramite il relativo ID.

16. Supabase, autenticazione e stato

Stato amministrativo

È presente la chiave localStorage padel_admin_state. Rappresenta lo stato/UI dell'amministrazione e non sostituisce il database.

Singleton Supabase

La parte pubblica utilizza window.sb e, dove previsto, __NP_SUPABASE_CLIENT__ per evitare client GoTrue duplicati.
